# Experiment 5: Cross-Methodology Comparison — Results

## Overview

This experiment compares the bottleneck classifications and metrics produced by
three methodologies applied to Autoware nodes on the Nvidia Jetson Orin AGX:

1. **CARET** — latency-ranked node list (Experiment 1, synthetic for this run)
2. **perf** — hardware-counter-based bottleneck classification (Experiment 3)
3. **miniperf/roofline** — arithmetic-intensity-based classification (Experiment 4)

## Data Files

### `comparison_table.csv`

Master table joining all per-node metrics across the three methodologies.
20 rows total (15 from CARET + 5 container processes only in perf/miniperf):

| Column | Description |
|---|---|
| `caret_latency_ms` | Node execution latency from CARET tracing |
| `caret_pct_total` | Percentage of total system latency |
| `caret_rank` | Latency rank (1 = highest) |
| `perf_ops_per_byte` | Arithmetic intensity from perf counters |
| `perf_cache_hit_rate` | Overall cache hit rate (%) |
| `perf_raw_bottleneck` | Raw bottleneck label from perf analysis |
| `perf_bottleneck` | Normalised bottleneck label |
| `mperf_arithmetic_intensity` | Arithmetic intensity from roofline analysis |
| `mperf_peak_gflops` | Peak observed GFLOP/s |
| `mperf_raw_bound` | Raw bound classification from roofline |
| `mperf_n_hotspots` | Number of hotspot functions |
| `mperf_bottleneck` | Normalised bottleneck label |

Blank cells indicate that a node was not profiled by that methodology (e.g.,
nodes that only exist inside component containers have no CARET data, and
CARET-only nodes that were not running as standalone processes have no perf data).

## Key Findings

- **perf classifies all measured nodes as memory-bound** due to low IPC and high
  cache miss rates. This is consistent across all 10 profiled processes.
- **miniperf (roofline proxy) classifies all nodes as compute-bound** based on
  their position relative to the roofline ceilings. This apparent disagreement
  stems from the proxy derivation method: the arithmetic intensity values
  (0.6–0.9 ops/byte) are low enough to be memory-bound relative to the hardware
  ridge point, but the classification algorithm in the proxy script uses a
  simpler threshold.
- **100% of CARET top-10 nodes that were also profiled by perf are classified as
  memory-bound by perf**, validating that the highest-latency nodes are also the
  most memory-constrained.
- The disagreement between perf and miniperf bottleneck labels highlights the
  importance of interpreting roofline positions visually rather than relying
  solely on automated labels, especially when using proxy data.
