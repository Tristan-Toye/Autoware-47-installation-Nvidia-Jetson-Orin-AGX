# Experiment 3: Perf Profiling — Results

## Overview

Hardware performance counters were collected via `perf stat` on 10 live Autoware
processes (a mix of standalone nodes and component containers) during a 30-second
rosbag replay on an Nvidia Jetson Orin AGX (aarch64).

## Data Files

### Raw per-node CSVs (`node_*.csv`)

One file per profiled process. Each contains the raw `perf stat` counters:

| Column | Description |
|---|---|
| `metric` | Counter name (`instructions`, `cpu-cycles`, `cache-misses`, etc.) |
| `value` | Counter value accumulated during the profiling window |

Profiled processes:
`behavior_planning_container`, `control_container`, `ekf_localizer`,
`map_based_prediction`, `mission_planner_container`, `motion_planning_container`,
`multi_object_tracker`, `ndt_scan_matcher`, `shape_estimation`,
`velocity_smoother_container`.

### `all_metrics.csv`

All raw counters merged into a single wide-format table (one row per node,
columns are counter names). Generated by `clean_perf_data.py`.

### `derived_metrics.csv`

Architecture-aware derived metrics computed by `analyze_perf.py`:

| Column | Description |
|---|---|
| `IPC` | Instructions per cycle — higher means better pipeline utilisation |
| `L1D_miss_rate_%` | Fraction of L1 data-cache loads that miss |
| `LLC_miss_rate_%` | Fraction of LLC references that miss |
| `MPKI_L1D` | L1D misses per kilo-instruction |
| `MPKI_LLC` | LLC misses per kilo-instruction |
| `MPKI_branch` | Branch misses per kilo-instruction |
| `memory_intensity` | Ratio of memory operations to total instructions |

### `agnostic_metrics.csv`

Architecture-agnostic metrics computed by `compute_agnostic_metrics.py`:

| Column | Description |
|---|---|
| `bytes_per_instruction` | Average memory traffic per instruction |
| `l1_to_llc_ratio` | Ratio of L1D miss rate to LLC miss rate |
| `bytes_per_cycle` | Memory bandwidth consumed per cycle |
| `ops_per_byte` | Arithmetic intensity proxy (instructions / bytes transferred) |
| `compute_memory_ratio` | Ratio of compute to memory operations |
| `l1d_reuse_ratio` | Data reuse factor in L1D cache |
| `overall_cache_hit_rate_%` | Effective cache hit rate across the hierarchy |
| `memory_op_proportion_%` | Fraction of operations that access memory |
| `primary_bottleneck` | Classification: `memory`, `compute`, or `balanced` |

## Visualisations (`visualizations/`)

| File | What it shows |

| `ipc_comparison.png` | Bar chart comparing IPC across nodes |
| `cache_miss_rates.png` | L1D and LLC miss rates per node |

| `memory_intensity_vs_ipc.png` | Scatter plot revealing compute vs memory trade-off |

## Key Findings

All 10 profiled nodes were classified as **memory-bound**. IPC values range from
~0.25 (map_based_prediction) to ~0.43 (control_container), well below the
theoretical maximum, indicating that most execution time is spent waiting for
data from the memory hierarchy rather than performing computation.
